# Правила версионирования

## Работа с ветками
1. Все изменения проводятся в отдельных feature-ветках.
2. Каждая ветка реализует одну фичу (например, `add-qudriga-import`, `implement-mlse`).
3. После завершения работы ветка объединяется с `main`.

## Комментарии в коде
- Минимальные комментарии, но обязательные:
  - Docstrings для модулей, классов и методов.
  - Пояснение сложных алгоритмов (например, детали MLSE).
- Названия переменных должны быть осмысленными (`bitstream`, `sampling_rate` вместо `bs`, `sr`).

## Версии
- Используется семантическое версионирование `MAJOR.MINOR.PATCH`.
  - `MAJOR`: Крупные изменения API.
  - `MINOR`: Новые фичи без ломающих изменений.
  - `PATCH`: Исправления багов.
